Версия ТЗ: 5.1  
Статус: готово к поэтапной разработке  
Тип проекта: Personal Learning PWA  
Основная платформа: iPhone (PWA)  
Язык интерфейса: русский

---

# 1. Общая концепция

## 1.1. Цель проекта

Создать персональное веб-приложение для изучения и закрепления знаний с помощью интерактивных карточек.

Приложение объединяет:

- Flashcards (вопросы и ответы)
- Интервальное повторение
- Бесконечные тренировки
- Адаптивный выбор вопросов
- Подсказки
- Систему уровней и опыта (XP)
- Достижения
- Аналитику обучения
- Отслеживание прогресса
- PWA для iPhone

Приложение используется одним владельцем для личного обучения.

Примеры направлений:
- Английский язык
- Разработка
- Тестирование
- DevOps
- Аналитика

Главная идея — превратить процесс изучения технических знаний в удобную систему тренировок с элементами RPG и профессиональной аналитикой.

## 1.2. Основные принципы

1. Mobile First — интерфейс прежде всего для iPhone.
2. Минималистичный технический дизайн.
3. Геймификация без избыточных игровых элементов.
4. Отсутствие микрофона и распознавания речи.
5. Пользователь самостоятельно отвечает на вопросы.
6. Пользователь самостоятельно оценивает правильность ответа.
7. Все данные сохраняются в базе данных.
8. Прогресс не должен теряться при закрытии приложения.
9. Возможность добавлять неограниченное количество карточек (в рамках лимитов хранилища).
10. Возможность расширять функциональность без переписывания архитектуры.

# 5. Два режима обучения

## 5.1. Режим A — интервальное повторение

Назначение: долговременное запоминание.

Каждая карточка имеет собственный график повторений.

Учитываются:
- Количество правильных ответов подряд
- Количество подсказок
- Ошибки
- Последнее повторение
- Следующее повторение
- Статус освоения

### Базовые интервалы

Первый правильный ответ без подсказок:
1 день

Второй:
3 дня

Третий:
7 дней

Четвёртый:
14 дней

Пятый:
30 дней

После пяти последовательных самостоятельных правильных ответов карточка получает статус MASTERED.

MASTERED не означает, что карточка никогда не появится снова.

Она возвращается на контрольные повторения.

### Правильный ответ с подсказками

Если использована одна подсказка:
- Не увеличивать серию самостоятельных правильных ответов.
- Назначить более раннее повторение.

Если использованы две подсказки:
- Не увеличивать серию.
- Назначить ещё более раннее повторение.

Начальные интервалы:
- 1 подсказка: 12 часов
- 2 подсказки: 3 часа

### Неправильный ответ

- Сбросить серию самостоятельных правильных ответов.
- Назначить повтор через 5–10 минут.
- Если карточка была MASTERED, вернуть её в активное обучение.

Интервалы являются стартовой конфигурацией, а не окончательной научно оптимизированной моделью.

Хранить интервалы централизованно.

### Важное правило

Карточка не должна бесконечно повторяться подряд.

Если есть другие доступные карточки, отдавать приоритет разнообразию.

Не показывать карточки раньше срока без отдельного действия пользователя.

## 5.2. Режим B — бесконечная тренировка

Назначение: свободная практика.

Пользователь выбирает тему и запускает тренировку без обязательного ограничения по количеству вопросов.

Карточки выбираются случайно с весами.

Слабые карточки имеют более высокую вероятность появления.

### Пример стартовых весов

Новая карточка:
5

Неправильный ответ:
10

Правильно с 2 подсказками:
8

Правильно с 1 подсказкой:
6

Правильно без подсказок:
3

Хорошо изученная:
1

Это пример базовых весов, которые можно будет настроить.

Необходимо избегать немедленного повторения одной карточки, если есть альтернативы.

### Важное правило

Бесконечная тренировка не должна автоматически изменять расписание интервального повторения.

Для этого необходимо разделить:
- Статистику свободной практики
- Статистику интервального повторения
- Расписание интервального повторения

Все ответы сохранять в общей истории с указанием режима.

## 5.3. Режим ошибок

Дополнительная тренировка по карточкам, на которые пользователь чаще всего отвечает неправильно.

Можно реализовать после основных двух режимов.

## 5.4. Выбор сложности

Фильтры:
- Все
- Easy
- Medium
- Hard
- Любая комбинация

Сложность задаётся вручную.

Уровень усвоения вычисляется автоматически.

Это разные параметры.

# 6. Геймификация

## 6.1. XP

Пользователь получает опыт за обучение.

Пример начисления:

Правильно без подсказок:
+10 XP

Правильно с 1 подсказкой:
+6 XP

Правильно с 2 подсказками:
+3 XP

Неправильно:
+1 XP за попытку

Завершение сессии:
+20 XP

Это начальные значения.

Не начислять бонус за завершение бесконечной сессии без минимального количества оценённых карточек.

### Защита от фарминга XP

Необходимо предусмотреть ограничения на повторное начисление опыта за одну и ту же карточку.

Пример:
- Полный XP за первое оценивание карточки в течение дня.
- Уменьшенный XP за последующие повторения.
- Ограничение XP за одну карточку в день.

Система должна поощрять обучение, а не бесконечное повторение простого вопроса.

XP не влияет на статус MASTERED.

## 6.2. Уровни

Уровень рассчитывается на основании общего количества XP.

Пример:

Level 1: 0 XP
Level 2: 100 XP
Level 3: 250 XP
Level 4: 450 XP
Level 5: 700 XP

Использовать единую формулу роста требований к XP.

Не хранить противоречащие друг другу значения уровня и опыта.

## 6.3. Достижения

Примеры:

FIRST STEP
Пройти первую тренировку.

100 ANSWERS
Ответить на 100 вопросов.

KNOWLEDGE MASTER
Выучить 50 карточек.

PERFECT RUN
Ответить правильно на 10 вопросов подряд без подсказок.

WEEK STREAK
Заниматься 7 дней подряд.

JAVA MASTER
Выучить определённое количество карточек по теме Java.

NO HINTS
Правильно ответить на 25 вопросов без подсказок.

Каждое достижение должно иметь уникальный код.

Повторно одно и то же достижение не выдавать.

## 6.4. Streak

Считать количество последовательных календарных дней, в которые была хотя бы одна засчитанная учебная активность.

Использовать локальную временную зону пользователя.

Не считать несколько тренировок за один день как несколько дней streak.

Не сбрасывать streak из-за перехода между UTC-днями, если локальная дата не изменилась.

## 6.5. Экран завершения тренировки

Показывать:

- Количество вопросов
- Правильные ответы
- Неправильные ответы
- Ответы с подсказками
- Точность
- Полученный XP
- Новые достижения
- Изменение уровня

Для бесконечного режима показывать результаты после ручного завершения.

# 7. Структура базы данных

Использовать Supabase PostgreSQL.

Все пользовательские таблицы должны быть защищены RLS.

## 7.1. profiles

Поля:

- id UUID PRIMARY KEY
- display_name TEXT
- timezone TEXT

- updated_at TIMESTAMPTZ

id связан с auth.users.id.

## 7.2. topics

- id UUID PRIMARY KEY
- user_id UUID NOT NULL
- title TEXT NOT NULL
- description TEXT
- icon TEXT
- sort_order INTEGER
- created_at TIMESTAMPTZ
- updated_at TIMESTAMPTZ

## 7.3. subtopics

- id UUID PRIMARY KEY
- user_id UUID NOT NULL

## 7.4. cards

- id UUID PRIMARY KEY
- user_id UUID NOT NULL

- question TEXT NOT NULL

- hint_1 TEXT
- hint_2 TEXT

## 7.5. tags

- id UUID PRIMARY KEY

## 7.6. card_tags

UNIQUE(user_id, card_id).

# 8. Алгоритм повторения

Алгоритм вынести в отдельные чистые TypeScript-функции.

Пример структуры:

src/features/learning/engine/

- spaced-repetition.ts
- weighted-selection.ts
- xp-calculator.ts
- level-calculator.ts
- achievement-rules.ts

Функции должны быть независимы от React.

## 8.1. Spaced Repetition

Входные данные:

- Текущий прогресс карточки
- Правильность ответа
- Количество подсказок
- Время ответа
- Текущее время

Результат:

- Новая серия правильных ответов
- Новый статус
- Следующая дата повторения
- Обновлённые счётчики

## 8.2. Weighted Random

Входные данные:

- Список доступных карточек
- История ответов
- Последние показанные карточки
- Фильтры

Результат:

- ID следующей карточки

Выбор должен быть случайным с весами.

Нельзя всегда выбирать только карточку с максимальным весом.

## 8.3. Тестирование алгоритмов

Обязательные сценарии:

1. Правильный ответ без подсказок.
2. Правильный ответ с одной подсказкой.
3. Правильный ответ с двумя подсказками.
4. Неправильный ответ.
5. Пять самостоятельных правильных ответов.
6. Ошибка после MASTERED.
7. Отсутствие доступных карточек.
8. Только одна карточка в теме.
9. Повторение одной карточки.
10. Переход между датами.
11. Бесконечный режим не меняет расписание.
12. Повторная отправка ответа не начисляет XP дважды.

# 9. PWA и сохранение данных

## 9.1. Основные требования

Приложение должно:

- Открываться в Safari.
- Устанавливаться на домашний экран iPhone.
- Запускаться в standalone mode.
- Иметь иконку.
- Иметь splash-compatible настройки.
- Корректно учитывать safe-area.
- Не терять уже сохранённые данные после закрытия.

## 9.2. Работа с сетью

Полноценный offline-first не требуется.

При отсутствии сети:
- Показывать понятное уведомление.
- Не утверждать, что ответ сохранён, пока сервер не подтвердил сохранение.
- Предотвращать случайное повторное отправление.
- Не переводить пользователя к следующей карточке с потерей несохранённого результата.

Допускается небольшая локальная очередь неподтверждённых ответов, если она будет реализована надёжно.

## 9.3. Восстановление сессии

После закрытия PWA и повторного открытия:

- Сохранённый прогресс остаётся в Supabase.
- Активную тренировку можно восстановить или завершить.
- Не должно возникать двойного начисления XP.
- Не должно появляться дублирующихся записей ответов.
