## Подтемы и просмотр

Подтемы строятся из `category` активных карточек загруженной темы. Для каждой показано количество карточек; есть пункт «Все подтемы». `NULL`, пустая строка и строка из пробелов отображаются как «Без подтемы». Имена поддерживают кириллицу и специальные символы. Выбор сложности (`easy`, `medium`, `hard`) работает вместе с подтемой; в UI видны русские названия. При пустом результате есть отдельное сообщение. Формы управления контентом не добавлялись.

## Серверная фильтрация и сессии

Новый RPC `start_filtered_training_session(topic, mode, category_mode, category, difficulty)` проверяет `auth.uid()`, активную тему, допустимые значения и наличие выбранной категории среди активных карточек владельца. Параметры фиксируются в `training_sessions.settings`. Список `spaced` и `mistakes` формируется сервером при старте сессии; в `infinite` каждая следующая карточка выбирается сервером по тем же фильтрам. Браузер не передаёт произвольные ID карточек для формирования списка.

Сохранён существующий уникальный индекс: одна активная сессия на владельца, тему и режим. Повторный старт с теми же фильтрами возвращает её ID. При других фильтрах RPC сообщает о конфликте и возвращает текущие фильтры. Интерфейс предлагает продолжить действующую сессию либо завершить её и создать новую. После обновления страницы URL и серверный `attempt_id` восстанавливают действующую попытку.

`next_training_attempt` проверяет фильтры и активность карточки перед выдачей. Карточка, удалённая или перемещённая в другую категорию после создания сессии, пропускается. Триггер перед вставкой в `answer_history` отклоняет ответ, если категория или сложность выданной карточки больше не совпадает с фильтрами сессии; транзакция не оставляет частичного прогресса. Точный повтор уже записанного ответа остаётся идемпотентным. Алгоритм интервалов, глобальный `card_progress` и отсутствие изменений расписания в `infinite`/`mistakes` сохранены.

Новых таблиц и прав записи браузеру нет. Добавлены один частичный индекс активных карточек, приватные функции проверки фильтров, триггер ответа и один публичный RPC только для `authenticated`. У `SECURITY DEFINER` RPC задан пустой `search_path`; доступ и владельца проверяют серверные функции. Старые сигнатуры RPC сохранены.

## Ручное применение к облачному Supabase

1. Сохранить резервную копию проекта обычным способом Supabase.
2. В Supabase Dashboard → SQL Editor выполнить **только** содержимое `supabase/migrations/20261110000100_training_filters.sql` в целевом проекте. Файл содержит одну транзакцию. Не запускать `db reset` и не применять миграции к удалённой базе через этот проект автоматически.
3. Развернуть обновлённый фронтенд после успешного применения миграции: новый экран вызывает `start_filtered_training_session`.
4. Проверить на существующих активных карточках: открыть направление, выбрать категорию и сложность, начать `spaced`; убедиться, что показаны только подходящие карточки. Повторить для `infinite` и `mistakes` (для последнего нужна карточка с `total_incorrect > 0`). Обновить страницу во время активной тренировки; затем попробовать другой фильтр того же режима и проверить выбор между продолжением и завершением сессии.

Учебный контент не добавлялся. Если в текущем проекте у карточек `category` не заполнена, они появятся в группе «Без подтемы».
