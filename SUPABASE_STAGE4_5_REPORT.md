## Модель и совместимость данных

`topics` — направления; `cards.section` — раздел; `cards.category` — группа вопросов; `cards.difficulty` — независимый фильтр. Новая колонка `section` допускает `NULL`, поэтому старые карточки и весь их прогресс сохраняются и отображаются как «Без раздела». Пустая строка и строка из пробелов также попадают в эту группу. Новых таблиц нет. У колонки есть ограничение длины; для поиска добавлен частичный индекс активных карточек по владельцу, направлению, разделу, группе и сложности. Браузеру не выдавались права записи в `cards` или защищённые тренировочные таблицы.

15 идентификаторов разделов Backend не зашиты в React. Список разделов и групп формируется из активных карточек Supabase. Пока карточек раздела нет, раздел не показывается. `01-java-core` отображается как «Java Core», а в URL и RPC сохраняется исходная строка. Числовые префиксы участвуют в естественной сортировке.

## Навигация

На странице направления можно выбрать «Все разделы» или конкретный раздел. После выбора раздела доступны его группы вопросов и «Все группы». У каждой кнопки показано число активных карточек. Фильтр сложности работает независимо. Карточки без группы обозначены «Без группы». Выбор «Все разделы» позволяет тренировать всё направление; фильтр сложности при этом сохраняется. Страница показывает карточки по разделам и группам, включая старый материал без раздела. Все выбранные фильтры сохраняются в URL и видны во время тренировки. На мобильном экране проверена ширина 320 px.

## Серверная фильтрация и защита

Новый `start_section_training_session(topic, mode, section_mode, section, category_mode, category, difficulty)` проверяет `auth.uid()`, активность и владельца направления, допустимые значения и существование выбранного раздела и группы среди активных карточек владельца. Сложность может дать пустую тренировку, не делая выбор раздела или группы недействительным. Фильтры записываются в `training_sessions.settings`; список конечной сессии формируется сервером, а `infinite` выбирает каждую карточку сервером. Клиент не передаёт список ID карточек.

Существующий уникальный индекс сохраняет одну активную сессию на владельца, направление и режим. Тот же набор фильтров возобновляет сессию, другой возвращает конфликт для выбора «продолжить» либо «завершить и начать новую». `next_training_attempt` повторно проверяет раздел, группу, сложность и активность карточки. Если карточка перемещена или удалена после выдачи, она пропускается. Триггер отклоняет новый ответ на уже выданную карточку, которая перестала соответствовать фильтрам; транзакция не оставляет частичной истории или прогресса. Точный повтор уже принятого ответа остаётся идемпотентным.

Ранее существовавшие сигнатуры `start_training_session`, `start_filtered_training_session`, `next_training_attempt` и `record_answer` сохранены. Старый `start_filtered_training_session` делегирует новому RPC с режимом «все разделы». Сессии, созданные до появления колонки, при чтении нормализуются как «все разделы», поэтому восстанавливаются без ложного конфликта. Для нового RPC использовано отдельное имя, а не перегрузка с параметрами по умолчанию. Все `SECURITY DEFINER` RPC имеют пустой `search_path`; `EXECUTE` нового RPC доступен только `authenticated`. Интервалы повторения и глобальный `card_progress` не менялись; `infinite` и `mistakes` не меняют график.

## Ручное применение

До применения новой миграции обновлённый фронтенд развёртывать не следует: он запрашивает `cards.section` и новый RPC.

Локальная повторная проверка:

```bash
npx supabase db reset --local
npx supabase test db
node scripts/test-training-concurrency.mjs
```

Для облачного проекта сначала проверьте резервную копию и убедитесь, что применены именно пять прежних миграций. Затем вручную выполните **только** содержимое `supabase/migrations/20261111000100_card_sections.sql` в Supabase Dashboard → SQL Editor. Файл уже содержит `BEGIN`/`COMMIT`; он не обновляет карточки или прогресс. Если миграции отслеживаются через Supabase CLI, согласуйте запись новой версии в истории миграций перед будущим `db push`, чтобы не повторить применение. После успешной миграции разверните фронтенд.

Вместо SQL Editor можно вручную выполнить тот же файл через `psql`, предварительно задав строку подключения через секретный менеджер:

```bash
psql "$KNOWLEDGE_CARDS_DB_URL" -v ON_ERROR_STOP=1 -f supabase/migrations/20261111000100_card_sections.sql
```

Используйте один способ применения. Прямой запуск SQL через Dashboard или `psql` сам по себе не отмечает версию в истории Supabase CLI.

Для ручной проверки достаточно существующих карточек: они должны быть видны в «Без раздела», тренировки и статистика должны работать как раньше. Разделы Backend появятся после отдельной миграции учебного контента. 20 вопросов Java Core в этом этапе не добавлялись.
