# Этап 5.1 — первые 20 вопросов Java Core

## Сделано

- Источник `cards/Backend/01-java-core/01-java-core-draft.yaml` прочитан целиком. В каждую из 20 карточек добавлен постоянный UUID `id`; тексты вопросов, ответов и остальные учебные поля не менялись.
- Добавлена миграция `supabase/migrations/20261112000100_java_core_content.sql`. Она привязана к переданному владельцем UUID учётной записи. Если активный `Backend` уже существует у этого владельца, используется его ID. Иначе тема создаётся с постоянным UUID. Другие владельцы не затрагиваются.
- Импортированы 1 направление `Backend`, 1 раздел `01-java-core`, 9 исходных групп и 20 карточек. Если направление уже есть, новых направлений не создаётся. Сложности: 18 `medium`, 2 `hard`.
- Поля `question`, `answer`, `category`, `difficulty`, `context`, `hint_1`, `hint_2`, `code` переносятся в одноимённые столбцы `cards`; раздел хранится в `cards.section`. Все `context` и `code` в источнике равны `null`; они остаются SQL `NULL`. Две карточки содержат по две подсказки, остальные подсказки остаются `NULL`.
- Миграция использует `INSERT ... ON CONFLICT (id) DO UPDATE` с проверкой владельца и направления. При повторном импорте UUID не меняются, а таблицы прогресса, ответов, попыток и сессий не изменяются. Мягко удалённые записи не восстанавливаются автоматически. Совпадение UUID с чужими или удалёнными данными приводит к ошибке.
- Браузерные права на запись контента не открывались. Приватная функция импорта недоступна ролям `anon` и `authenticated`.
- Добавлены проверка YAML и генератор снимка миграции `scripts/generate-java-core-import.mjs`, SQL-тест `supabase/tests/database/java_core_content_test.sql`, E2E `tests/java-core-content.spec.ts`; обновлена инструкция `supabase/content/README.md`. Для YAML-парсера добавлена dev-зависимость `yaml` в `package.json` и `package-lock.json`.

Существующий интерфейс уже читает активные темы и карточки с `section`, `category`, `difficulty`, обоими hint-полями и остальным содержимым. Алгоритм повторений не менялся.

## Ручное применение в облаке

1. Убедитесь в Dashboard → Authentication → Users, что учётная запись владельца с переданным UUID существует. Проверьте миграцию и YAML в репозитории.
2. Просмотрите список ожидаемых изменений:

   ```bash
   npx supabase db push --dry-run --remote
   ```

3. Если список содержит только ожидаемую новую миграцию, примените её вручную:

   ```bash
   npx supabase db push --remote
   ```

4. Войдите в приложение и проверьте Backend → Java Core → группы, затем начните `spaced`-тренировку. До ручного применения облачная база и приложение на реальных данных не изменятся.

После применения этой миграции не редактируйте её. Для исправления вопроса создавайте следующую версионированную миграцию с тем же UUID карточки, обновляя запись на месте; учебный прогресс при этом сохраняется.
